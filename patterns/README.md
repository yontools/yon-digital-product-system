# Patterns

Patrones reutilizables para problemas frecuentes de producto digital.

Cada patrón debería documentar:

- problema
- contexto de uso
- solución
- cuándo usarlo
- cuándo NO usarlo
- variantes
- trade-offs
- estado (`proven`, `experimental`, `deprecated`)
- evidencia o referencia cuando exista

La biblioteca debe favorecer soluciones simples y reutilizables, no acumular componentes por cantidad.
