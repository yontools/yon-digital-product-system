# YON Blueprint

Create or refine a Product Blueprint before implementation when the product is broad, multi-role, workflow-heavy, or contains meaningful reusable capability composition.

## Run

1. Understand the requested outcome, users, participants, relationships, jobs, workflows, constraints, and existing behavior.
2. Run capability discovery when reusable behavior is uncertain or broad.
3. Resolve the minimum capability composition.
4. Check relevant patterns and evidence.
5. Create or update a Blueprint using `blueprints/BLUEPRINT-TEMPLATE.md`.
6. Separate reusable capabilities from product-specific behavior.
7. Record genuine gaps and their disposition.
8. Identify high-risk boundaries and verification gates.
9. Define implementation order and unresolved questions.
10. Do not implement merely because a Blueprint exists; pass the Blueprint into the build step.

## Output

Return the completed Blueprint or a concise decision summary containing:

- outcome and success criteria;
- participants/relationships;
- critical workflows;
- entities/lifecycle;
- capability and pattern resolution;
- composition boundaries;
- product-specific requirements;
- gaps and assumptions;
- risks and verification;
- implementation order;
- unresolved questions.

Do not publish reusable knowledge automatically. Respect the project privacy boundary.
