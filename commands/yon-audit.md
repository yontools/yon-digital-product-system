# /yon-audit

## Purpose
Audit an existing digital product before making changes.

## Instructions

1. Inspect the repository and identify the application architecture.
2. Run the product when possible.
3. Map the important routes and workflows.
4. Identify primary users, roles and critical tasks from available evidence.
5. Audit UX, UI, accessibility, responsive behavior, performance, content, error handling and business workflow.
6. Look for repeated manual work, unnecessary clicks, hidden actions and automation opportunities.
7. Separate observations from assumptions.
8. Rank findings by impact, confidence and effort.
9. Do not implement changes unless requested or clearly required by the task.

## Output

Return:

- Executive summary
- Critical issues
- High-impact opportunities
- UX findings
- UI findings
- Workflow/automation opportunities
- Accessibility/responsive findings
- Technical risks
- Recommended next actions

Never invent product requirements that are not supported by the repository or user context.
