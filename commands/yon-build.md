# /yon-build

## Purpose
Build a new digital product from requirements while applying YON from the beginning.

## Instructions

1. Clarify the product goal, users, roles, workflows and constraints from available requirements.
2. Define the smallest useful product surface before expanding scope.
3. Establish information architecture and primary workflows.
4. Design core states before polishing visuals.
5. Choose architecture and dependencies appropriate to the existing environment.
6. Build reusable components and consistent interaction patterns.
7. Treat responsive behavior and accessibility as part of implementation.
8. Run the product early instead of waiting for a fully finished implementation.
9. Verify critical workflows in the browser.
10. Fix issues discovered during verification.

## Avoid

- feature inflation;
- unnecessary dependencies;
- placeholder UX left in production paths;
- fake functionality presented as complete;
- generic visual decoration without product purpose.

## Completion

A build is complete only when the core user journey works end-to-end and the resulting product has been verified in its running environment.
