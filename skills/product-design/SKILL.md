# Product Design

## Objetivo
Convertir necesidades reales en productos que resuelvan problemas con el menor esfuerzo posible.

## Principios

1. Entender antes de diseñar.
2. Diseñar para resultados, no para cantidad de funcionalidades.
3. Reducir pasos, decisiones y carga cognitiva.
4. Mantener consistencia entre pantallas y estados.
5. Diseñar estados vacíos, errores, carga, éxito y casos límite.
6. No agregar complejidad si no genera valor.
7. Validar con el producto funcionando.

## Proceso

`OBSERVE → UNDERSTAND → DETECT → PROPOSE → IMPLEMENT → VERIFY`

## Preguntas

- ¿Quién usa esto?
- ¿Qué intenta conseguir?
- ¿Qué información necesita en ese momento?
- ¿Qué puede automatizarse?
- ¿Qué acción debería ser obvia?
- ¿Dónde puede equivocarse?
- ¿Qué podría eliminarse?
- ¿Cómo medimos si mejoró?
